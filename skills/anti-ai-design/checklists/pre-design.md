# Pre-design checklist

Use during discovery. Each item: answer, mark *(assumed)*, or mark *(not relevant)*. Ask the user only about items that are decisive and not inferable.

## Product and people

- [ ] What the product does, in one sentence
- [ ] Primary user: role, expertise, frequency, context of use
- [ ] Primary task, in one sentence
- [ ] Other key tasks, ranked by frequency × importance
- [ ] Business/product objective for this work

## Platform and technology

- [ ] Target platforms and devices (web/desktop/mobile; OS versions if native)
- [ ] Input methods (touch, pointer, keyboard, stylus)
- [ ] Stack inspected: framework, styling, component library, build
- [ ] Existing design system/brand located (tokens, components, guidelines), or confirmed absent
- [ ] Closest existing screens/components identified for reuse

## Constraints

- [ ] Accessibility target (default assumption: WCAG 2.2 AA)
- [ ] Performance constraints (devices, network, bundle budget)
- [ ] Localization (languages, RTL, text expansion)
- [ ] Legal/brand restrictions
- [ ] Effort/time constraints, and whether the user wants exploration or direct implementation

## Content

- [ ] Real content available? If not, realistic shapes and lengths known
- [ ] Assets available (photography, illustrations, product screenshots, logos with permission)
- [ ] Data shapes and edge cases (empty, long, many)

## Interactions

- [ ] Required interactions (forms, editing, real-time, drag and drop, offline)
- [ ] States needed (loading, empty, error, success, permissions)
- [ ] Persistence and navigation behavior (URLs, back, drafts)

## Before moving on

- [ ] Assumptions written down
- [ ] At most one or two decisive questions asked (or defaults chosen)
- [ ] Next workflow and reference files selected
